# Registro de decisiones

Cada decisión se apunta con fecha, motivo y quién la tomó (`Usuario` o `Claude`). Las decisiones de diseño vienen del documento `docs/2026-10-29-base-datos-vivienda-design.md`, secciones 5.1 a 5.4.

|---|---|---|---|
| 2026-10-29 | Esquema por organismo; una hoja de datos por tabla; hipervínculo desde Tablas. | Organizar el catálogo por fuente y poder navegar desde Tablas a cada dato. | Usuario |
| 2026-10-29 | `CREATE TABLE` por tabla dentro del catálogo, listo para copiar y pegar. | Facilitar la creación de la base de datos MySQL. | Usuario |
| 2026-10-29 | Mismo formato de fecha y de todo en todas las tablas. | Coherencia entre tablas. | Usuario |
| 2026-10-29 | Claude descarga todos los datos desde `URL datos / API` (o `URL ficha` si no hay); el formato intermedio (CSV, XLS…) es indiferente. | Descarga automatizada y reproducible. | Usuario |
| 2026-10-29 | Python para descargar y transformar; los scripts serán la base de la ETL futura. | Reutilizar el código en la ETL futura. | Usuario |
| 2026-10-29 | Maestro Territorios como referencia de códigos y nombres de territorio. | Códigos INE unificados en todas las tablas. | Usuario |

| 2026-10-29 | Grupo Territorio: `nivel` ENUM, `cod_territorio` (ES / CAxx / PRxx / MUxxxxx), `cod_ccaa`, `nombre_ccaa`, `cod_provincia`, `nombre_provincia`, `cod_municipio`, `nombre_municipio`. | Códigos y nombres INE tomados de Maestro Territorios. | Claude |

| 2026-10-29 | Grupo Control: `provisional` TINYINT(1) (0 salvo que la fuente marque provisionalidad) y `fecha_descarga` DATE. | Trazabilidad del dato y de cuándo se obtuvo. | Claude |
| 2026-10-29 | Formato largo: una fila por territorio × dimensiones × periodo. | Modelo homogéneo y consultable con SQL. | Claude |
| 2026-10-29 | Cortes de serie: si una fuente publica la misma medida en varias bases o metodologías, cada base es una serie separada mediante una dimensión `base` que entra en `id_registro`. | 2026-10-29 | Revisiones: la carga reemplaza el valor anterior (UPSERT) y `fecha_descarga` deja constancia de cuándo se obtuvo. El historial completo queda para la fase de ETL. | Decisión del usuario; el historial se deja para más adelante. | Usuario |
| 2026-10-29 | Esquemas `MIVAU`, `NOTARIADO` e `IDEALISTA`. Nombres de tabla `organismo_tema_detalle` en minúsculas y de 64 caracteres como máximo. | Convención de nombres para la base de datos. | Claude |
| 2026-10-29 | Hojas de datos con nombre corto (31 caracteres como máximo, límite de Excel); el nombre completo vive en Tablas y el hipervínculo une ambos. | Límite de nombres de hoja en Excel. | Claude |
| 2026-10-29 | En CCAA uniprovinciales (Madrid, Asturias, Baleares, Cantabria, Murcia, Navarra, La Rioja, Ceuta, Melilla) se generan también las filas de nivel Provincia copiando el valor de la CCAA. | 2026-10-29 | Maestro Territorios: se añade cabecera; la búsqueda de alias se hace por (alias, nivel) porque hay alias repetidos entre CCAA y provincia. Se amplía con municipios (y secciones censales si SERPAVI lo requiere) a partir del INE cuando una tabla lo necesite. | Alias repetidos entre niveles; cobertura de municipios cuando haga falta. | Claude |
| 2026-10-29 | Correcciones del libro existente: `provisional` `#REF!` → 0; columna `KPIs` `#VALUE!` → vacía con nota; se eliminan el vínculo externo a `Dils_Catalogo_Fuentes_DWH_2.xlsx` y los 49 nombres definidos que dependen de él; `fecha` pasa de número de serie a fecha; se completan textos truncados de Tablas desde General. | Errores y dependencias externas del libro original. | Claude |
| 2026-10-29 | Ceros: se conservan como 0 si la fuente trae 0; si trae `-`, `..` o vacío se guarda NULL. Se documenta por tabla. | Distinguir un cero real de un dato ausente. | Claude |
| 2026-10-29 | Si un dataset de General contiene varias medidas o tablas en origen (p. ej. MIVAU-31205000 con desgloses, ETI), se decide en ese momento si es una tabla con dimensión extra o varias tablas, y se documenta. | Caso por caso, al tratar cada fuente. | Claude |
| 2026-10-29 | Fuente de verdad: `Data Dils.xlsx` sigue siendo el libro del usuario y nunca se sobrescribe. Los scripts leen de él General, Campos y Maestro Territorios (solo lectura) y generan un libro nuevo de salida. Cuando el usuario lo valide, decide si sustituye al original. | Preservar el original del usuario. | Claude |
| 2026-10-29 | Desgloses que no son territorios INE (tamaño de municipio, municipios de más de 25.000 habitantes, comunidad del comprador, extranjeros residentes) van como dimensiones propias de la tabla, nunca como códigos inventados en Maestro Territorios. `cod_territorio` es siempre un territorio INE real. Con dos territorios por fila, el principal es el de la vivienda y el otro va en `cod_ccaa_comprador` / `nombre_ccaa_comprador`. | Evitar códigos inventados; mantener `cod_territorio` como territorio INE real. | Claude |
| 2026-10-29 | Fuentes del MIVAU sin fichero descargable: si solo publica tablas HTML en su web, se extraen de ahí (datos públicos de la Administración). Se documenta en la ficha de la fuente. No aplica a Idealista ni al Notariado. | No hay fichero descargable; los datos son públicos. | Claude |
| 2026-10-29 | Fuentes sin descarga (Notariado ×2, Idealista ×2): se catalogan con diseño completo (Tablas, Campos, `CREATE TABLE`) pero sin datos en fase 1. | 2026-10-29 | Catálogo fuente de verdad en etl/catalogo/*.csv, sembrado desde el Excel del usuario. | El Excel del usuario es solo lectura; el catálogo versionado en CSV alimenta el SQL y el libro de salida. | Claude |
